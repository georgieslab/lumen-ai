# Milestone 3 — Five functional desk actions

The desktop provides five separate draggable action pills. The Customize desktop icon (also in Settings) lets people show or hide each action, enable older tool shortcuts, hide Persona/weather, or restore the default layout and positions. Visibility and positions are saved in this browser. Each pill has a hide button on hover or keyboard focus. Explore always provides the actions on desktop. Smaller screens replace floating pills and widgets with a spatial glass Tools window containing grouped everyday actions, local search across all 13 tools, and an All tools view. The background stays locked while it is open, with keyboard focus restored on close. Each planning/research action has an editable brief, review step, and durable mission with visible progress, pause, resume, and saved outputs.

## Behavior

- **Plan my day:** uses an explicit date, IANA time zone, start time, availability, priorities, and the selected conversation’s unfinished checklist/schedule state. The agent creates actual schedule and checklist cards; complete dated schedules can export calendar files. Optional city context enables a weather lookup.
- **Decision desk:** compares at least two named options against user-supplied criteria and constraints. Live research is enabled for this action; the comparison and recommendation must separate facts, assumptions, and unknowns.
- **Verify this:** accepts up to 6,000 characters of claims, a passage, or a public URL. The evidence tool creates up to six supported/contradicted/unresolved claim entries. Conclusive verdicts require at least one source page actually read. Search-only evidence stays unresolved. Every cited URL must have appeared in a successful search or page read in the current mission, including checkpointed research after a resume. Cards distinguish search-result evidence from pages actually read. These checks establish citation provenance; the model’s interpretation still requires judgment.
- **Watch this:** persists a public URL or search topic, interval, status, next due time, last good baseline, and change notifications. Public-page watches compare normalized extracted text, capped at 40,000 characters. Topic watches compare canonical result URLs and titles, sorted to avoid alerts caused only by ranking or tracking parameters. Initial and unchanged observations stay quiet. Failures retain the previous baseline and back off. Successful changes save a before/after excerpt and in-app notification together.
- **Project spaces:** create, edit, archive, and reopen private projects. Add working instructions and up to ten plain text reference files; pin a whole mission or individual artifact; reopen recent work. A matching spatial glass container groups context, files, pins, and missions, with a sidebar on desktop and a horizontal workspace picker on phones. Personal and project conversation context stays separated, including restored missions and local artifact edits.

## Scope and storage

Projects reuse the existing authenticated identity or confirmed HttpOnly guest mission cookie. Mutations require a trusted Origin. Projects, missions, watches, and notifications enforce ownership on the server. Pins reference existing outputs and cannot attach another project’s or owner’s mission. Web observations use the existing public-address and redirect guards.

Private atomic JSON storage defaults to `.lumen-data/projects`, `.lumen-data/watches`, and `.lumen-data/missions`. Configure `LUMEN_WORKSPACE_STORE_DIR`, `LUMEN_WATCH_STORE_DIR`, and `LUMEN_MISSION_STORE_DIR` on persistent storage. This implementation expects one server process; shared multi-process scheduling needs a database and distributed job coordination.

Limits: 30 active projects per owner; 12,000 instruction characters; 100,000 characters per TXT/MD/CSV/JSON file and 400,000 combined reference/instruction characters; 100 pins per project. New mission context includes at most 20,000 combined file characters with truncation flags. Stored project files are reference data, never authorization. PDF/image project indexing is not included; the existing request-scoped attachment path remains available.

Watches allow 20 nonarchived and 100 saved records per owner, 50 retained notifications, two concurrent observations, a 60-second observation timeout, and intervals of 15 minutes/1 hour/6 hours/24 hours. `LUMEN_WATCH_ACTIONS_PER_HOUR` defaults to 60 per authenticated visitor or IP. Checks run only while the server is online; the browser can be closed. Delivery is in-app, without push, email, or SMS. JavaScript-rendered/authenticated pages are not supported. Text comparison can detect cosmetic changes and does not determine their importance with AI.

## Validation

Automated checks cover owner/origin protection, project and file limits, atomic restart recovery, scoped pins, durable watch schedules, single-flight checks, unchanged/failure behavior, notification persistence, request deduplication, bounded action contracts, source provenance across resumed runs, canonical topic observations, and project conversation isolation. Browser verification exercises forms and real missions, project persistence/pins, watch controls, and desktop/phone layout.
